Objetivo do dia:
1. Criar o modelo de dados de playbook (coleção Firestore `playbooks`), NÃO reutilizar visita-template como playbook (templates de visita continuam existindo).
2. Tipos TypeScript em src/types/index.ts:

   PlaybookPhase = 'preparacao' | 'durante' | 'encerramento'
   PlaybookItemKind = 'task' | 'activity' | 'document'

   PlaybookItem:
   - id: string
   - kind: PlaybookItemKind
   - phase: PlaybookPhase
   - title: string
   - description?: string
   - offsetDays: number  (relativo à startDate da visita; negativo = antes)
   - durationMinutes?: number  (só activity)
   - startTime?: string        (só activity, HH:mm opcional)
   - location?: string         (só activity)
   - documentCategory?: DocumentCategory  (só document — metadado, sem arquivo)
   - assigneeName?: string
   - order: number

   Playbook:
   - id, name, description?, visitType (string livre, ex: "Institucional")
   - items: PlaybookItem[]
   - ownerId, createdAt, updatedAt
   - isDeleted? (soft-delete se o padrão do projeto encaixar; senão delete real ok neste CRUD)

3. Service src/services/playbooks.ts: create, listByOwner, get, update, delete.
   Listar só os do owner (admin vê todos, igual visitas).
4. Validação Zod em src/lib/validations.ts (nome obrigatório, items com title/kind/phase/offsetDays).
5. Rules em firestore.rules:
   - read: dono ou admin
   - create: autenticado e ownerId == auth.uid
   - update/delete: dono ou admin
   - Não permitir cliente criar playbook.
6. UI de CRUD em Configurações (nova seção ou subpágina /configuracoes/playbooks).
   - Lista de playbooks (nome, tipo de visita, qtd de itens).
   - Dialog criar/editar: nome, tipo, descrição.
   - Editor de itens: adicionar/remover/reordenar (order).
   - Campos do item: kind, phase, title, offsetDays, responsável (texto), extras conforme kind.
   - Reutilizar Card, Dialog, Button, Input, Select, PageHeader.
7. Item de navegação só se fizer sentido (Configurações já existe). Não criar rota no sidebar principal hoje.
