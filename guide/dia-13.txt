Estado atual:
- Activities: title, description, location, date, startTime, endTime, visitId,
  responsibleNames. startTime já no formato `${date}T${HH:mm}:00`.

- Conexão Google via Functions (refresh token no servidor).

Objetivo do dia:
1. Campo opcional na Activity: `googleEventId?: string`.
   Types + map + updateActivity. Não quebrar atividades antigas.
2. Callable HTTPS `syncActivityToGoogle` (activityId) e `deleteGoogleEvent` (activityId
   ou eventId). A Function:
   - valida auth.uid (owner da atividade ou membro com escrita)
   - lê tokens da conexão Google do uid (se a atividade é de outra pessoa, sincroniza
     no calendário de quem está logado — documente isso)
   - insert/update Google Calendar event:
     summary = activity.title
     description = visita + description
     location = activity.location
     start/end com timeZone America/Sao_Paulo (ou timezone do usuário se já existir)
   - grava googleEventId na activity (Admin SDK)
3. No frontend, depois de create/update/delete/move em AgendaPage (e WeeklyAgenda):
   - se getCalendarStatus().connected, chamar o sync (fire-and-forget com toast de erro
     se falhar; não bloquear o save local).
   - delete local → deleteGoogleEvent.
4. Conflitos:
   - Manter o conflito interno atual da AgendaPage.
   - Extra: na Function, freebusy.query no intervalo do evento. Se busy, a Function
     devolve { conflict: true, hint }. O frontend mostra toast.warning
     "Conflito no Google Calendar" mas AINDA assim pode criar o evento (ou perguntar).
     Prefira: avisar e criar mesmo assim, para não travar a operação.
   - Se freebusy falhar por escopo, fique só com o conflito interno e registre TODO no código.
5. Não sincronizar o histórico inteiro automaticamente. Botão na Agenda:
   "Enviar programação desta visita ao Google" (loop das activities da visita atual).
