Objetivo do dia:
1. Criar src/services/playbookApply.ts (ou função no service de playbooks) `applyPlaybookToVisit`.
   Entrada: playbookId, visitId, ownerId, startDate da visita (ISO yyyy-MM-dd).
   Para cada item, na ordem:
   - kind task: createTask com title, assigneeName, dueDate = startDate + offsetDays,
     status backlog, order crescente. Se dueDate cair fora, ainda assim gravar a data calculada.
   - kind activity: createActivity com title, description, location, date = startDate + offsetDays,
     startTime/endTime a partir de startTime + durationMinutes (default 60 min).
     Se startTime ausente, usar 09:00. Formato de tempo igual ao restante do app
     (Agenda usa `${date}T${HH:mm}:00`).
     responsibleNames: [assigneeName] se houver.
   - kind document: NÃO fazer upload. Criar um registro "placeholder" reutilizando a coleção
     `documents` SOMENTE se der para ter um doc sem arquivo; caso as rules exijam storagePath,
     criar coleção `documentPlaceholders` (visitId, title, category, phase, ownerId) com rules
     iguais às de documents. Prefira a opção mais simples que compile e respeite rules.
2. Função auxiliar addDays(isoDate, offsetDays) — visitClone.ts já tem addDays/diffDays privados;
   extrair para src/lib/date.ts (ou similar) e reusar no clone + no apply, sem duplicar lógica.
3. Botão no detalhe da visita (VisitDetailPage.tsx): "Aplicar playbook".
   - Dialog: select de playbooks do owner.
   - Confirmar. Se a visita já tiver tarefas, avisar ("vão ser adicionadas, não substituídas") e seguir.
   - Toast de sucesso com contagem (N tarefas, M atividades, K documentos).
4. Opcional mas desejável: ao criar visita no NewVisitDialog, se o usuário escolher um playbook
   (select separado do template de visita), chamar applyPlaybookToVisit depois do createVisit.
   NÃO remova o DEFAULT_CHECKLIST ainda (dia 3). Se playbook for escolhido, NÃO aplicar o checklist fixo
   no mesmo create (evita duplicar tarefas).
5. Prazos relativos: dueDate e activity.date sempre derivados de visit.startDate + offsetDays.
   Se a visita mudar de data depois, NÃO reagendar automaticamente hoje.
6. Registrar activityLog resumido: action apply_playbook, visitId, summary com nome do playbook.
